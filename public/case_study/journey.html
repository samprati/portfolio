Remote Property Management — how the whole system flows

Work happens offline (an agent physically visits); the product's job is to turn that reality into visible proof on a distant owner's screen. Everything below is one data spine, seen through four roles.

The four roles

One system, four surfaces

Each role sees the same underlying objects — a unit, an inspection, a ticket, the ledger — rendered for what only they need.

🛰️

Owner

Mobile · B2B web

The distant investor (NRI / cross-city). Sees the truth, approves the money.

🔑

Tenant

Mobile portal

Pays rent, raises issues. Sees maintenance status only — never the owner's money.

📷

Field Agent

Mobile · offline-first

Captures physical reality: checklist, geotagged photos, before/after proof.

🗂️

Ops / Admin

Web console

Dispatches agents, resolves disputes, manages the vendor registry.

The hard part

Maintenance & money — the approval gate

The friction is deliberate: nothing moves the owner's money without a tap. Rent payout for the unit is held the moment a ticket opens.

OPEN tenant raises + payout held→ VERIFYING agent: photos + quote→ NEEDS APPROVAL
owner approves→IN REPAIR →VERIFYING FIX after-photos ok · funds released→CLOSED ✓
owner rejects→CLOSED · REJECTED
owner asks question→NEEDS INFOagent replies↺
fix fails / contested→DISPUTEDOps resolves w/ photo trail→
Guards that keep it honest: can't reach IN REPAIR without an Approval object · can't close without after-photos · payout stays held until the ticket is terminal · every state change writes a ledger row + timeline card + proof link — no silent money movements.
Status at a glance

The health state — the object everything pivots on

One rule above all: health never improves without proof. A red never clears because time passed — only because an agent verified it.

Green — healthy

Last inspection clean, no open tickets, sensors nominal. The default the whole product is fighting to maintain.

Amber — attention

Minor inspection flag, a sensor warning, or an open ticket. Something to watch, not yet urgent.

Red — critical

Leak, structural, pest, squatter, or an unresolved ticket past SLA. Surfaces first on every board.
